Gateway isolation UX

Explore how Gateway isolation changes the Windows identity and session used to run OpenClaw, where the setting is managed, and why the Gateway must not be able to remove its own outer containment boundary.

Proposed

Gateway isolation setting

Compare enabled and disabled

Enabled is the recommended Windows posture. Disabled removes the Agent User boundary and runs the Gateway as the signed-in user. It is an explicit advanced, reduced-containment choice.

Naming transition (September 8, 2026): Earlier drafts called Enabled Minimal and Disabled YOLO. PM input resolved the user-facing terminology to enable or disable Gateway isolation.

Configuration surfaces

One host authority, two experiences

clawctl owns the host lifecycle. When isolation is disabled, the Control UI can invoke the enable operation. When enabled, it can only report status.

Trust boundary

The Gateway can tighten isolation, not remove it

The host launcher remains authoritative. The native Gateway can request the safer transition, while the isolated Gateway cannot remove its own boundary.

Disabled Control UI Runs as the signed-in user and offers Enable isolation.
→
clawctl gateway-isolation enable Requests a host-owned lifecycle transition.
→
Host launcher Validates the request, provisions the session, and restarts the Gateway.
Enabled Gateway Runs as the Agent User and exposes no Control UI action to disable isolation.
×
clawctl gateway-isolation disable Remains available only from the signed-in user's host context, with an explicit warning or --force.
→
Host-owned state Is not stored in openclaw.json and is validated on every start.

Do not conflate these controls

Gateway isolation versus inner command sandbox

Enabling or disabling Gateway isolation chooses the Gateway's Windows identity and session. MXC presets choose restrictions for individual commands after the Gateway is already running.

Gateway isolation

Enabled or disabled. Owned by the Windows host launcher and managed through clawctl or the safe Control UI enable action. Establishes or removes the outer Agent User Session.

MXC command sandbox preset

Locked Down, Recommended, or Unprotected in current working implementations. Owned by the Gateway MXC plugin or Windows node for nested, per-command ProcessContainers.
